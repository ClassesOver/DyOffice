# GenOffice PDF 编辑器接入 Web

目标：工作区直接复用 GenOffice PDF 编辑器的功能区、缩略图、画布和编辑状态，接入现有 Web 文件版本、Office 助手、频道和交付。

1. 将桌面编辑器的保存请求映射到 Web 的统一 PDF 保存接口。原始页索引、批注作者和文档版本必须保留；未接通的编辑整批拒绝，防止保存后桌面清除了实际未写入的草稿。验收：隔离数据库中混批仅生成一个版本，重读成品并比对原版。
2. 给桌面渲染器装配 Web 文件宿主与独立构建入口。宿主根据会话、文件和已确认版本访问字节；不把磁盘路径、Electron 文件对话框或原始 IPC 开放给浏览器。验收：Chromium 从工作区打开文件，渲染功能区、缩略图和页面；保存、重开及提交回执丢失可恢复。
3. 接入原文编辑和其余 Web 已支持的 PDF 编辑能力。验收：用编辑器直接操作并保存重开，核对未编辑的文字、页面、表单和批注。
4. 接入共享 Office 助手、外接 DSH 频道和交付写回；保留现有 Web PDF 编辑与批注能力。验收：真实模型委派、父任务自动续跑，报告从历史恢复并插入，保存重开后可读。
5. 在替换工作区入口之前逐项核对桌面工具、现有 Web 工具、只读状态及降级行为。保护、签名、附件和导出单独验收；未接通的控制应清楚显示不可用。最终以 Chromium 实际加载和操作为准。

当前进展：通过 `nativePdfDirectory` 装配独立入口 `/native-pdf/`，直接加载 GenOffice PDF 渲染器。Chromium 与隔离 PostgreSQL 已验证授权打开、功能区、翻页、旋转保存，以及连续两次丢失回执后再次点击保存。三次请求使用同一提交输入，最终仅新增一版；编辑器读取确认后的版本，重开可读，原件字节不变。隔离数据库另验证高亮、便笺、新增文字、页结构和元数据可混批保存。

原生入口已接共享 Office 助手的模型目录、对话与频道。浏览器验证从功能区打开和收起、调用工具读取当前 PDF 第二页、流式回复。设置 `DYOFFICE_DSH_NATIVE_PDF_DIR` 可将 DSH 验收切换到原生入口；真实模型与官方 DSH 已验证委派、自动续跑、重新登录后恢复同一交付，并将报告和来源哈希作为附录写入新页。追加草稿时版本不变，显式保存后重开可读，原件字节未变。

`office-tool-inventory.test.mjs` 另验证原生 PDF 的默认内置 Harness 路径：确定性模型不传执行器标识，Chromium 在任务完成前看到实时输出，完成后父对话收到工具结果并继续。测试使用固定 Harness 适配器。

已有原文改写已接入桌面文字引擎和 Web 批量保存。服务端用原始页索引和选区定位内容，拒绝无匹配的整批请求；浏览器验证同页重复文字只替换点选的一处，旋转和原文改写共用同一保存版本，丢回执后恢复，重开可读。手工改写也已复用 PC 的提前匹配、字形边界及原色检查。浏览器验证点选蓝色文字后编辑框保留原色，手工改写与助手修改共同保存并可独立回读。隔离 PostgreSQL 验证未匹配返回原因、拒绝其他账号与过期版本，校验不提交文件。

已有便笺可在原生界面编辑，已与原文改写、旋转一起在 Chromium 验证保存并重开。HTTP 回归另验证重排页面、编辑指定便笺及删除指定标记在一次保存中完成，同位置的另一条便笺和原作者均保留，原版不变。

原生 PDF 助手已接全文搜索、文字标注、短文字原文改写、整段改写和段落移动。改写和移动复用桌面定位和排版及 Web 保存预检，通过后进入待保存草稿。Chromium 以固定模型响应验证同页两处相同文字时拒绝不存在的第三处，只替换指定的第二处；整段改写保留同页标题，右对齐后下移 10 点。混合保存仅新增一版，回执恢复后重开可读，原件不变。

`native-pdf-harness.test.mjs` 在 Chromium 和隔离 PostgreSQL 中验证内置 Codex CLI 和外接计算适配器两条写回路径。助手读取原文、发现计算代理，经真实任务 API 委派计算，再用回执结果同时改写原文和已有便笺。显式保存前文件版本未变；保存只新增一个版本，独立读取确认正文与便笺一致、原作者与历史版本字节保留，刷新后可重读。模型响应使用确定性测试夹具；真实上游模型与生产 Harness 的这条混合编辑链路仍待验收。

同一用例文件另验证运行中刷新：同一登录会话和页签恢复原任务编号、指令和进度，原 Office 对话随后收到 Harness 结果。核对任务只派发一次、原对话只恢复一次、原文只改写一次，用户消息不重复；手动保存前版本不变，保存重开后正文和原对话均可读，原件字节保留。

检查点同时记录模型已经读取的对话轮次。Chromium 验证续跑后再追问，较早的问答在模型请求中只出现一次。面板回归也验证任务先完成、宿主后就绪时，即使没有新的任务事件仍会继续原对话。

父对话续跑按原工具调用恢复。共享 AgentLoop 的可选检查点已在原生 PDF 启用：同一回合只发出一个 `delegate_agent_task`、本轮尚未改写文档且历史不含内联图片时，可以在工具执行期间保留有限大小的模型上下文。续跑把 Harness 结果按原工具调用 ID 配回，不从头重发用户请求；模型网关接受历史调用和结果，续跑回合不开放新的 Harness 委派。

已接入短时任务记录和一次性续跑。浏览器本地仍只保存任务 ID；检查点按原账号、会话、文件、文件版本及模型绑定，普通状态查询不返回检查点。新版客户端读取检查点时不消耗它，模型网关准入首个续跑请求时才消耗。HTTP 与隔离 PostgreSQL 回归验证丢失读取响应可重读、并发只允许一次模型续跑，失效会话、文件回收站、错误文件及过期版本均拒绝。当前页面意外断开 Harness 流时，通过状态接口查询原任务，收到结果后继续对话，不重新派发。

刷新后的原生编辑器通过同一接口读取检查点，回复更新原聊天记录；编辑器不干净或原模型不可用时不自动续跑。如果在模型回复期间产生了新草稿，助手在首次编辑前停止。进程重启、模型准入后再次断开及已经开始产生改写的回合不自动重放。Word、XLSX、PPTX 已在各自的 Chromium 用例中验证原对话只继续一次、原生写回，以及关闭自动保存时显式保存才产生新版本。

设置 `DYOFFICE_LIVE_PDF_HARNESS_CONFIG` 为已授权共享聊天模型的私有 JSON 配置路径（顶层 `entry`），可运行同一用例的真实模型与本机 Codex CLI 分支。验收检查父对话实际收到 Codex 生成的 `total.json`、两项原生编辑的工具回执及保存后的 PDF，不以模型回复声称成功作为证据。该分支使用隔离 PostgreSQL 和自建 PDF；正式运行隔离另行验收。

`npm run build:saas` 包含原生 PDF 资源。服务检测到原生构建资源后，工作区默认使用 GenOffice 原生编辑器，无需设置开关。浏览器验证工作区加载、取消关闭后保存按钮仍可用、撤销后可关闭。

新增文字草稿支持插入、列表、按编号编辑、移动和删除。Chromium 使用固定模型回包调用五项工具，混合保存后独立读取成品，确认保留块的最终文字及坐标、删除块未落盘，回执重试没有新增版本。

原生 PDF 助手支持读取批注、新增便笺、按编号编辑和回复、删除便笺线程及删除文字标注。Chromium 使用固定模型回包验证编辑已有便笺并回复后保留原作者和回复关系；被删除的草稿便笺及下划线不写入成品，同页高亮保留。所有修改通过显式保存合并为一个版本。

原生 PDF 助手已接桌面 `apply_ops` 与 `list_form_fields`，两者使用原始页号。Chromium 使用固定模型回包验证试运行及无效批次均不留下旋转草稿；有效批次将第二页旋转、已有字段赋值及标题更新合到一次显式保存。回执重试仅新增一版，重开可读，原件保留。

原生 PDF 助手已接 `get_outline` 和 `insert_blank_page`。Chromium 验证读取真实书签、读取尚未保存的空白页，以及插页与其他修改同批保存。重开后空白页仍在，尺寸与相邻页旋转后的显示尺寸一致。

原生 PDF 的水印与页眉页脚草稿接入 Web 统一保存，保存时按最终页序生成页码。Chromium 使用固定模型响应验证两项助手工具与插页、旋转、编辑、批注一同保存，丢回执后仍只新增一个版本；重开后清除已保存的水印，页脚和原始版本保留。服务端回归另验证重排、替换水印以及重复操作校验。已保存印记的清除结果在保存后显示。

原生 PDF 助手已接 `insert_image`，复用桌面的图片定位和草稿操作。媒体浏览器回归通过 6 项，其中原生入口验证搜索结果与 WebP 生图短引用可插入，GIF 和 WebP 链接可转换，显式保存后独立核对三张嵌入图的像素，重开可读，原件字节不变。模型和媒体响应使用测试数据。

原生 PDF 助手已接 `list_page_images`、`transform_image`、`rotate_image`、`replace_image`、`delete_image`。Chromium 验证同页共享底层图片资源的四处引用可独立移动、替换、删除和旋转，成品像素及位置符合预期，原件不变。

原生 PDF 助手已接翻转、裁剪、透明度和去背景，沿用 Web 像素处理器预检，通过后进入编辑器撤销栈。Chromium 验证四种操作与同页其他图片操作同批保存，检查了翻转后的颜色、裁剪后的边界、透明度、去背景后的透明边框与保留主体，重开可读且原件字节不变。助手的四类图片草稿现共用写入引擎生成的临时 PDF，画布和缩略图在显式保存前即可显示处理后像素。Chromium 与隔离 PostgreSQL 验证翻转方向、裁剪露出的底色、透明像素混合、去背景保留的主体以及撤销/重做；预览期间文件版本不变，保存后独立回读像素。功能区手工选图已接入同一版本的图片列表、像素读取和原位擦除预览。Chromium 与隔离 PostgreSQL 验证手工水平翻转、撤销/重做、裁剪、50% 透明度和去背景，并与原文改写、批注及表单同批保存。保存回执丢失后确认得到同一新版本；独立读回图片像素及文字内容，原版本字节不变。

同页手工与助手图片草稿共用合成后的局部预览。Chromium 使用三处共享同一图片资源的绘制验证：功能区翻转两侧图片后，助手翻转中间图片，画布与缩略图均显示翻转；撤销只恢复中间图片，重做后显式保存，独立读取三处成品像素，原版本不变。助手工具使用固定模型响应。该用例的三图混合编辑现在使用带已勾选复选框的 AcroForm；保存后对比字段树、控件和值及外观流均一致。隔离 worker 另验证带已填写文字字段与复选框的翻转，旧版草稿入口验证带表单的透明度预览和保存。现有加密、已签名和 XFA 拒绝规则仍通过回归。

带普通 AcroForm 的 PDF 已通过兼容入口的图片插入、移动和替换浏览器回归。固定模型调用工具后，Chromium 与隔离 PostgreSQL 验证暂存一次、丢失回执后恢复同一提交、重新读取图片位置和像素，并独立核对原复选框的字段和值及外观。服务端另验证同批移动、旋转、删除、替换与透明度，明确拒绝加密、已签名和 XFA 文件。

原生 PDF 助手从工作区打开时可用 `create_document` 创建独立 PDF，工作区启用 DOCX 编辑时也可创建 DOCX。Chromium 使用固定模型响应验证默认 PDF、显式 DOCX、切换到新文档以及保存回执与正文一致；源 PDF 的版本和字节保持不变。

创建 PDF 或 DOCX 时，Web 助手与 PC 一样先拒绝误贴的工具回执标记与原始文档块 JSON。单测验证两种格式均不发起创建，换成正常 HTML 后可重试；原生浏览器回归验证正常 PDF、DOCX 仍可保存并独立回读。
