# Word 含图片文档打开性能（2026-11-24）

样本为 50 页 Word 文档，包含 600 个可见内容块、50 张不同的 PNG，文件大小 5,276,780 字节，SHA-256 为 `4d6260997f36891b29c4405fb26da6b184ee79584e7a2a3bb5e029966a702c06`。改动位于 DOCX 引擎：每张需要内嵌显示的图片读成字节后直接编码，复用同一图片的引用仍共享结果。

| 指标（中位数）                           |   优化前 |   优化后 |  缩短 |
| ---------------------------------------- | -------: | -------: | ----: |
| Chromium：发起文档解析到收到后台线程结果 | 572.4 ms | 432.2 ms | 24.5% |
| Chromium：导航到编辑器报告文档就绪       |  2188 ms |  2108 ms |  3.6% |
| Node：解析完整 DOCX                      | 449.8 ms | 214.8 ms | 52.2% |

浏览器使用 Chromium 151.0.7922.34 和本机 HTTPS，前后两份生产构建按 AB、BA、AB、BA 的顺序各打开四次。每次使用独立浏览器上下文和文件副本，并确认编辑区可用。按轮次取整到毫秒，首屏用时分别是 2979 / 2195 / 2181 / 2142 和 2557 / 2190 / 2027 / 1988。首屏变化小于单组波动；后台解析四轮均缩短。测试服务未启用 Word 协作，打开时协作接口返回 404，两组一致。Node 24.18.0 在两次独立运行中各预热一次，再测七次解析；不含下载、渲染和保存时间。

八次浏览器打开均通过后台线程完成解析且读到 50 张图片。修改正文、保存并重新打开后，验证新文字和 50 张图片均保留，保存包里的每张 PNG 均与原始字节一致。另在 Chromium 中分别启用、禁用原生 Base64 编码接口，逐一对比解析出的图片数据 URL，结果与原图一致。本次未测纯文字文档、协作或弱网条件。
