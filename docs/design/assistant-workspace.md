# Office 助手与 harness 协作区交互设计

日期：2026-11-18。状态：可交互设计稿，尚未替换运行页面。

## 目的与范围

将现有 Office 助手、内置 Codex、服务端注册的外部 adapter 与频道外接 Agent 放进同一个容易理解的协作区。保留当前左侧面板和文档编辑区的位置。优先覆盖 Web DOCX/XLSX；不暗示当前关闭助手的格式已支持。

现有能力证据：`createEditorAssistant` 将模型选择、频道管理和分析交付放在同一个 `modelPicker` 插槽；`AssistantParticipants` 只渲染名称；`createCodingClient` 通过 Office 工具委派内置/服务端 harness；`createAssistantChannelClient` 支持邀请、申请批准、外接委派、取消和持久状态。

## 布局

1. 标题栏：AI 助手、协作入口、当前文档。头像使用统一的 30px 图标容器，来源通过文字标识。
2. 对话 / 助手 / 任务三个视图。对话是默认页；助手页负责身份和接入；任务页汇总执行与结果。三个视图共用底部输入区，切换不卸载聊天执行器。
3. 对话中保留 Office 的自然语言说明，委派显示可折叠任务卡，包含执行方、来源、真实状态、详情和取消。
4. 输入框顶部显示“发送给 Office 助手 / Codex / 某外接助手”。点击展开对象选择器，包含职责及不可用原因。默认 Office，正常对话可按需委派。
5. 输入框底部只放紧凑的模型选择、原有必要工具与发送按钮。模型名保持单行、长名截断并可查看全名；不把频道表单或分析交付列表塞在底部工具条。
6. 产物跟随任务卡展示；所有产物在任务视图集中查找。区分“生成结果”“插入文档”“保存文档”，复用已有交付及保存收据。

默认宽度沿用宿主面板，设计稿以 408px 展示；验收 320/360/400px、长中文名与长模型名、浅色/深色。普通操作目标不小于 30px，高频选择行至少 40px。键盘可切换对象、选择模型、关闭弹层；状态更新使用 aria-live，输入法组合期间不触发发送。

## 身份与状态

| 对象 | 展示 | 模型归属 | 可提供的动作 |
| --- | --- | --- | --- |
| Office 助手 | 主助手；文档问答与协调 | 当前 Office 模型 | 对话、查看能力 |
| 内置 Codex | 内置；代码、数据处理、图表 | 当前 Office 模型，经现有代理 | 交给它、查看任务及失败原因 |
| 服务端外部 adapter | 外接；注册的能力名称 | 由 adapter 契约确定，不统一猜测 | 按能力委派、查看任务 |
| 频道外接 Agent | 外接；连接状态、授权范围 | 外接端管理，除非协议显式提供模型控制 | 委派、查看授权、移除 |

注册与健康状态分开：有 catalog 只说明“已配置”，未运行验证时显示“运行待验证”；成功事件仅证明对应任务完成。频道已批准但尚未建立连接应显示“等待连接”。不通过名字或绿色圆点猜测在线，不把注册成功当成运行成功。

缺少 harness 时仍显示 Office；助手页明确当前无可用 harness，区分服务端关闭、目录加载失败、未连接。只有现有 API 能证实的原因才展示。保留可用的 Office 对话，不静默替换用户选定的目标。

## 关键交互

- 选择对象只影响下一次发送，保留输入草稿和已有任务；发送时冻结目标身份与模型。原型不启动模型，示例状态始终标明。
- Office 模式发送进入现有 AgentLoop；内置/服务端 harness 直接提交必须复用 coding client 的能力校验和取消，不拼接一句“请用某助手”假装完成显式路由。
- 频道模式复用 channel.send，发出后进入排队状态；回执不代表执行完成。外接助手离线或暂停时显示原因，不自动切换 Office。
- 共享输入区下，附件/选区必须按目标能力显式授权。目标切换不自动外发当前文档或带走整个历史。不支持的输入保留并说明，而非悄悄丢弃。
- 内置执行状态来自请求开始、返回、错误与取消确认；不伪造逐步日志或百分比。频道保留 queued/running/waiting_peer/cancel_requested/succeeded/failed/cancelled/unknown_outcome。
- 取消后展示“正在取消”；收到确认才显示“已取消”。结果不明确时提供核对入口，不一键自动重跑可能已执行的任务。
- 外接接入按“生成限时邀请 → 对方申请 → 展示身份和请求权限 → 批准 → 等待连接 → 已连接”。没有真实邀请链接格式时不编造二维码。邀请收起、过期后隐藏。
- 移除助手明确撤销该连接权限；保留任务历史。暂停仅作用于外接协作，Office 对话继续。
- 模型选择器显示真实配置名称（如 ds），不自行替换为推测的模型产品名。频道外接目标显示“由外接助手管理模型”。

## 实施边界

视觉可以统一，执行契约暂不强行合并。内置/注册 harness 是有界 SSE 调用，频道 Agent 是持久异步任务；两者用各自稳定 ID 和来源构造显示项，不能用同名合并。

首批：新增独立协作区插槽，将频道、交付移出 modelPicker；共享参与者组件升级为入口；保持现有 Office 对话、草稿和执行器生命周期。此批可落地统一视觉与已有协作能力。

第二批：增加显式发送目标，抽出复用的 coding run 操作及轻量任务订阅；Docs/Sheets 发送时冻结目标、模型和授权输入；与现有原生运行队列协调。涉及接口变化，须针对原生对话、委派、并行输入、取消和失败保留草稿测试。首期不宣称刷新能恢复内置正在运行的进程。

第三批：真实环境验收。使用已配置模型与安装的 Codex 完成一个有产物的小任务；通过受支持的外接 adapter 完成邀请、审批、委派与返回。真实调用前检查当前服务开关及 catalog；当前截图不能证明运行服务已接入。

## 验收条件

- 320px 面板无中文标签折行、按钮遮挡、页面水平溢出；弹层不被输入框裁剪。
- 可识别三类身份、目标、模型归属；未启用/离线/未验证状态不误报可用。
- 切换视图、目标和模型不清空草稿，不打断已有任务；任务使用发送瞬间的绑定。
- 直接提交命中选定执行方；外接离线不会自动发给其他对象。
- 邀请、审批、暂停、移除以及任务取消都能看到等待、成功和失败反馈。
- 内置注册、真实执行与真实端到端验收分别记录，不能以原型或模拟测试替代。
- 结果下载、受支持的插入、保存仍以已有权限检查和真实回执为准。
