# DyOffice 验收矩阵、性能基线与证据模板

> 版本 1.0 · 2026-11-15。所有条目初始为 `not_run`，不是通过记录。
> 任务编号对应 [implementation-plan.md](implementation-plan.md)；设计依据见 [architecture.md](architecture.md)。

## 1. 状态与放行规则

统一状态：`not_run`、`running`、`passed`、`failed`、`blocked`、`not_applicable`。缺少模型、数据库权限、字体、原生组件、浏览器或客户样本时记 blocked，并记录解除条件。只有具有明确范围解释并获责任人确认的非核心功能才可 not_applicable；四格式真实打开/编辑/保存/重开、隔离和恢复不能这样排除。

P0 是安全、数据完整性和企业核心链路；失败立即阻断发布。P1 是承诺范围内的重要能力，生产签收前关闭。P2 是不影响安全/数据与关键使用的体验问题，可有责任人、期限和已知限制说明。系统或供应商故障不得混同为模型内容质量失败。

每次执行绑定 Git commit、依赖锁/容器摘要、DB schema、配置版本、浏览器、引擎、模型/Provider、MCP 协议/SDK/客户端版本。不同版本的成功证据不能拼成同一个 release 的“全通过”。

## 2. 测试环境与数据

T00 建立拟建的 `apps/web/test/helpers/services.ts`、`apps/web/test/compose.yml` 和隔离 fixture 存储，启动独立 PostgreSQL、S3 兼容服务和需要时的 Redis；T03 加测试 OIDC IdP。CI 不访问真实生产库和生产密钥。T23 的部署包与该测试环境分开，防止把方便测试的默认密码或公网端口带到生产。

测试用户至少 A、B、配置管理员、运维、审计员；企业独立部署还需两个不同 deployment 配置验证域名/配置隔离。真实服务用最小权限测试账号。原生组件、字体、浏览器必须在镜像/环境清单中记录。

基准数据建议至少每格式 10 个常规和 10 个边界样本，共 80 个；另加客户授权的至少 20 个代表样本或由客户确认的等效覆盖集。优先复用上游已许可 fixtures，再补合成或脱敏文件。每个样本记录 sha256、生成方式/来源许可、期望修改、不可变部件、视觉/语义断言和支持能力。测试文件不得包含未获授权的真实个人/业务秘密。

边界覆盖：中文/英文及复杂文字、字体缺失、分页/表格/页眉、公式/日期/单位/图表、母版/嵌入对象、扫描 PDF/签名/密码、损坏 ZIP、极高压缩比、超大媒体、外部链接、恶意内容。外部 Word/Excel/PowerPoint/PDF 阅读器复开证据由可使用该软件的 QA/客户环境提供，不伪造为本地自动测试结果。

## 8. 性能与稳定性目标

下述是压测起始目标，T00 建立基线、T25 在冻结环境验证。调整须由业务/技术负责人在试点前确认；不能失败后悄悄调低门槛。

基准负载建议：100 个已认证会话、25 个活跃编辑器、10 个并发 AI run、最多 4 个原生任务同时运行；缓存冷热分别报告。另做 1.5 倍目标负载过载测试，验证排队/429/隔离而不是无限增长。硬件、网络 RTT、带宽和样本必须写进结果。

| 指标 | 起始目标 | 测量口径 |
| --- | --- | --- |
| 文件列表/偏好/元数据 API | p95 <= 300 ms | 服务端计时，排除模型和大文件传输，记录 p99 |
| revision 最终提交 | p95 <= 500 ms | 字节已验证上传后，到 DB 提交应答；不含上传/序列化 |
| DOCX 50 页、5 MiB | 首次可编辑 <= 5 s | 规定客户端/网络，冷启动另报 |
| XLSX 100,000 个非空单元格、5,000 公式 | 首次可操作 <= 8 s | 声明引擎/原生解析耗时，公式正确性不能为速度让步 |
| PPTX 30 页、10 MiB | 首屏可编辑 <= 5 s | 其余页可渐进加载，不能阻塞全部 UI |
| PDF 100 页、20 MiB | 首页面可阅读 <= 3 s | 不要求全部页面同时完成渲染 |
| 模型流 | 网关附加延迟单独统计 | 首 token 与供应商耗时分别报告，不作无依据固定承诺 |
| 会话撤销传播 | 长连接 <= 30 s | 新的敏感写操作立即重验授权，不等待传播窗口 |
| 稳定性 | 至少连续 24 h | 无不可恢复内存增长、跨用户泄漏、重复持久写和文件损坏 |
| 恢复 | RPO <= 15 min、RTO <= 4 h | 企业标准建议，基于真实一致性恢复结果 |

保存成功率不能把业务 409 冲突当服务器故障，也不能把失败写入从统计中删掉；分别记录合法请求成功率、冲突率、可重试失败和数据完整性事件。负载达不到目标时，先明确瓶颈/容量/限制，不能在销售材料中宣称通过。

## 9. Release Gate

### Gate A：内部可运行

T00–T08 的边界、身份、文件一致性和 DOCX 闭环通过；没有真实服务条件的部分清楚标 blocked。只能称内部可运行版本。

### Gate B：企业试点候选

四格式核心 F01–F04、全部 P0 身份/保存/执行边界、真实模型、MCP 与客户必要数据源通过；部署包、漏洞修复、基础恢复演练和支持矩阵齐备。客户确认数据进入试点环境的权限。

### Gate C：生产放行

本 release 所有适用 P0/P1 通过，P2 有责任人和期限；真实端到端查询/报告、目标 Harness、客户 IdP、压力和恢复目标通过；高危安全问题关闭；试点业务签收；回退窗口、负责人和制品完成。未运行的能力不得进入产品声明。

### Gate D：运营接管

客户/服务团队能独立处理告警、轮换密钥、停用用户、备份恢复和升级；支持渠道有效；使用/成本/错误指标可见；交付责任与保留策略签收。代码 merge、镜像 build 或演示成功都不能替代本 gate。
