# Office 助手数据源分析与连接范围

2026-11-20，`feat/dyoffice-web` 工作区（基线 `55a1022b` 加本次工作区变更），本机测试环境。客户数据未用于自动测试。

## 启用与回退

默认开启：本地账号模式（`DYOFFICE_AUTH_MODE=local`）下，只要配置了模型网关（`DYOFFICE_PROVIDER_GATEWAY_PROFILES` 或 `DYOFFICE_CONFIG_KEYRING`）和数据源凭据密钥（`DYOFFICE_SOURCES_CREDENTIAL_KEYS`），未设置 `DYOFFICE_ASSISTANT_SOURCE_CATALOG` 时即按 `read-only-analysis` 启动；任一条件缺失则自动保持关闭，不影响启动。显式设置的值始终优先：`off` 关闭，`metadata-only` 只列当前工作区启用的连接名称和标识；显式设为非 `off` 而条件缺失时启动失败，并列出缺少的配置。判断集中在 `apps/web/server/assistant-source-mode.mjs`。设为 `metadata-only` 或 `off` 并重启后，服务端不再开放直接分析路由，模型网关也不再接受这些工具。

未在管理员数据源出站白名单中的 SQL 主机只能解析到公网地址；企业内网数据库（例如客户 StarRocks）需先由管理员加入白名单。重开编辑器可更新工具列表。回退不删除工作区已有数据结果。保存连接配置后，旧版本的临时结果不能继续读取或委派；已正式保存的数据结果仍按原有的工作区权限管理。

账号菜单的「数据连接」与「全局配置」使用同一套独立设置页面容器。打开连接后可切换「连接设置」「可见范围」「高级配置」。在「可见范围」读取保存后的连接，再勾选目录和表，可用手工输入补充。目录限定可访问的数据库或 Schema；表范围在这些目录里进一步筛选具体表。选择「仅指定」后未勾选任何项表示不开放，两项都设了限制时取交集。仅配置页可探查账号可读的候选项，Office 的目录、字段和查询仍按已保存的限制执行。MySQL 和 StarRocks 的候选目录限定为绑定的数据库；PostgreSQL 候选目录为该数据库内可用的用户 Schema。

## 真实模型多轮成功率（2026-11-22）

用 `tools/dyoffice/analysis-eval` 统计（用法见该目录 README）：生产代码的 AgentLoop、数据源技能、插入技能、只读 SQL 路径、快照和截断提示，接真实模型；数据库是 `seed.sql` 生成的合成销售数据（2.4 万订单、4.8 万明细，超过单次 1000 行上限），文档为记录插入内容的内存目标。评分与数据库直接算出的真值比对，数值须与对应的季度、月份或类别同行出现。5 个场景各 3 次：

| 场景 | gpt-5.6-luna | gpt-6.1-sol |
|---|---|---|
| 发现表结构后按季度汇总（2 轮） | 3/3 | 3/3 |
| 明细请求被截断后改为库内聚合 | 3/3 | 3/3 |
| 渠道汇总作为表格插入 Word | 3/3 | 3/3 |
| 跨表类别排名并在追问中沿用口径（2 轮） | 2/3 | 3/3 |
| 月度金额写入 Excel 单元格 | 2/3 | 3/3 |
| 合计 | 13/15 | 15/15 |

两次失败：一次用户说「华南区」而数据取值为「华南」，模型查到实际取值后停下来询问而未计算（已在提示中要求映射明确时直接使用并说明）；一次插入表格失败，未保留工具输出，单独复跑 4 次均通过（评测报告现记录每次工具调用的输入与报错）。

评测发现并已修复的产品问题：SQL 策略拒绝 `EXTRACT(... FROM ...)`、`INTERVAL '1 month'` 和 `::double precision`；`generate_series(...) AS g(x)` 的列别名被重新生成为标识符 `"g(x)"` 导致查询失败（现直接拒绝 FROM 中的列别名列表）；数据库的语法、字段或类型错误被报为「结果不可用」（现为可修正的 400 并给出改写建议）；未带 Schema 的表名查不到字段时，模型误以为表不可读（现在空结果中提示使用带 Schema 的全名）。

仍未覆盖：编辑器原生工具和浏览器界面（由浏览器用例覆盖）、PostgreSQL 以外的方言、客户 StarRocks。
