# T05a immutable object and validation foundation

2026-11-15, baseline `6a9fe63e`, branch `feat/dyoffice-web`. This is the first part of T05. It adds tested storage/validation primitives; it does not yet expose authenticated upload routes, file metadata, quotas, recycle-bin operations or document editing. The local account server still returns 501 for unimplemented file operations, and production remains guarded. Full T05 is not complete.

## Implemented contracts

`ObjectStore.putImmutable(key, bytes)` snapshots the input before asynchronous I/O, computes SHA-256 and size, and publishes an object once. Even a second put with identical bytes fails with 409. Keys are canonical UUID deployment/owner/object namespaces generated by trusted server code, not filenames or paths. `readVerified(reference)` bounds data to the trusted reference length and recomputes SHA-256 before returning bytes. Missing, truncated, overlong or same-size-corrupted data fails closed. No URL, ETag or user metadata replaces the hash check. Object references remain internal; a later service must authorize their owner before reading.

The local adapter requires a dedicated directory and refuses symlink roots/objects. It writes an exclusive temporary file, fsyncs it, atomically hard-links without replacement, fsyncs the parent and removes the temporary name. It is a development, single-node adapter, not shared-replica storage or protection against a hostile process with the same filesystem privileges. Crash leftovers need the future reference-aware retention collector; no eager deletion is added here.

The S3 adapter takes an explicitly configured SDK client and private, precreated bucket. Conditional PUT uses `IfNoneMatch: '*'` and a base64 SHA-256 checksum; reads consume and hash the actual body under a byte bound. Both operations have a 30-second abort deadline. It never issues public/presigned URLs, creates buckets or configures credentials/encryption policy. IAM, TLS, encryption, retention, replication and recovery must be supplied and verified by deployment work. The conditional-write/checksum behavior follows [AWS PutObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html) and [SDK checksum guidance](https://docs.aws.amazon.com/sdk-for-javascript/v3/developer-guide/s3-checksums.html).

`validateUpload(bytes, name)` returns immutable format/MIME/size/SHA-256 metadata without rewriting originals. Input is limited to 32 MiB. DOCX/XLSX/PPTX require a genuine OPC ZIP package with content types, an internal root Office relationship and the format's canonical main XML/root namespace. Metadata children resolve their inherited/default/prefixed namespace; local-name matching alone is insufficient. Names reject path/control/bidi input. ZIP checks reject traversal, aliases/duplicate names, symlinks, encryption, macros, ZIP64 and split archives. Every entry is streamed through bounded inflation, its actual length/CRC checked, and local/central metadata compared. Defaults: 4096 entries, 32 MiB per part, 128 MiB total inflation, 4 MiB per structural XML. Structural XML rejects DTD/entities and invalid syntax. These are initial development budgets, not measured enterprise capacity.

PDF requires an actual parsed, unencrypted document with at least one page and a valid header/trailer, rather than a `%PDF` prefix. Originals are not saved/repaired by pdf-lib. This is structural preflight, not a fidelity/signature/feature certification or malware scan. OOXML Strict namespaces, noncanonical main part names, encrypted/macro packages and ZIP64 are currently rejected rather than advertised as supported.

Parsing runs in a worker with a five-second deadline and a 128 MiB old-generation JS heap limit. At most two workers run per validator; excess requests return temporary 503 with no unbounded wait queue. Deadline/worker failure terminates the worker and releases capacity. Worker resource limits do **not** cap all external Buffer/native allocations or provide an OS security sandbox. Hostile PDF decompression and complete parser containment still require the T21 process/container memory/sandbox gate before public exposure. This checkpoint deliberately does not wire the validator to a public upload endpoint or claim complete F13 acceptance.

## Actual verification and review

Tests began RED because the new adapters/validator were absent. Real local-disk and S3 tests then passed for immutable publication, concurrent single-winner writes, corruption, length/hash mismatch, missing objects, namespace escape and symlinks. Additional tests reproduced mutable caller buffers causing a mismatched stored hash (local) or S3 checksum rejection; snapshotting fixed both. Parser concurrency initially admitted three jobs and the deadline API was absent; worker admission/deadlines passed their RED-to-GREEN regressions.

Fresh independent read-only review found one Important issue: incorrectly namespaced Override/Relationship children were accepted. A real JSZip-generated regression reproduced acceptance, then passed after namespace-aware resolution. Correct prefixed OPC metadata remains accepted. No other review finding was reported within this checkpoint's scope. The reviewer ran local/parser tests, not S3 writes; author verification separately used the actual S3 service. No second review is claimed. Historical T03c action-token retention remains deferred.

The real S3 compatibility fixture uses RustFS pinned at `sha256:b81d16a90ee25bd9511280127ca1471788c6e874cf0f0da759645f46b2dc1d74`, loopback-only, disposable tmpfs and random local credentials. MinIO image retrieval failed (registry denial/unavailable); substituting a real S3-compatible test service does not select a production storage product. The CI configuration pins the same digest, nonroot tmpfs ownership and readiness probe. Its exact default image command/environment/tmpfs combination was started locally and returned readiness 200; no GitHub Actions success is claimed. Compatibility with this service is not evidence for every enterprise S3 backend or HA durability.

Structural fixtures cover valid generated packages, fake ZIP/PDF, extension/type mismatch, path attacks, encryption/macros, DTD, wrong namespaces, corrupted CRC, local/central name disagreement, entry/part/total/XML/input limits and underdeclared inflation. Existing repository DOCX, blank XLSX, business PPTX and plain PDF fixtures pass; an encrypted PDF fixture is refused. The deadline test kills a real worker, and subsequent healthy work succeeds.

These are local observations, not a production, all-backends, operating-system sandbox or customer-acceptance claim. Root and standalone Web lockfiles are synchronized; new dependency versions/integrities are included in the compatibility inventory.

## Next work and rollback

T05 continues with migration 5, FORCE RLS and grants for files/uploads, quota reservation under concurrency, scoped stage/byte-transfer/finish, initial immutable references, authenticated open/download and recycle/restore. Metadata must never reference an incomplete object; objects written before a failed database commit remain unreferenced until safe reference-aware cleanup. Ownership and revocation must be revalidated at final commit. T06 later adds revision CAS, leases, idempotency and history; initial file import must not masquerade as the editing-save protocol.

No migration or user deployment was changed by this foundation. Reverting it removes unused new modules, tests and dependency additions; it does not delete stored objects or alter existing prototype state. Preserve test and checkpoint evidence while the full implementation plan remains active.
