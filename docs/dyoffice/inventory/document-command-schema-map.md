## Minimum safe P0 completion boundary

1. Strict immutable identity/profile/control envelope with exact keys; no production assembly.
2. Handle, renewal, stop/adopt, result/artifact types plus structural validators clearly separated from authorization and actual process observations. Stop/instance observations require the full expected handle. Artifact structure binds expected handle/requestId/export/generation, but validateCommandResult accepts only the source-backed PPTX outline reply; all others refuse.
3. Runtime policy metadata matches code, productionEnabled=false for every format.
4. Every known mapped engine operation is either fully schema-validated or explicitly refused. No generic JSON reply success path exists. High-level operation classification is not engine dispatch permission.
5. Missing format schemas stay listed above with source and next task; no fabricated cross-format command API, no blanket `unknown`/JSON pass-through.
6. Full deep engine import/export inventory remains distinct from this first source map. Review must not mark full Task 1 complete merely because common control types compile.

The next dependency-cohesive implementation work is to extract schema-only shared modules from actual engine/API definitions without importing document parsers into the API/broker. PPTX outline is the first schema-only example below. Continue with XLSX open/close contracts, then the larger cells/render/mutation graphs. Mutation/export commands must additionally bind generation, attempt, lease and exact sealed output before they are eligible for T06.

## Implemented read-only PPTX outline wire schema

Evidence at the baseline above: `worker/src/native/pptx-session.ts:318-321` checks expected generation; `:334-336` constructs count/size/slideIds/paths; `:455-456` appends optional defaultFont; child `:503` calls `session.outline(raw.expected)`. The new protocol uses `{profileId:'pptx-edit-v1', command:'outline', args:{expected}}`; this is a schema-only translation of that existing method, not a wired child transport. Reply wrapper binds complete ExecutionHandle, requestId, command and generation from trusted outstanding-request state. No parser package is imported.

`packages/pptx-engine/src/identity.ts:43-46` defines slide IDs: final slideN.xml yields s_N, otherwise s_ plus path with non-alphanumeric characters replaced by underscores. The schema verifies this correspondence without renaming either field and rejects duplicate path/ID ambiguity. `zip.ts:151-159` only guarantees positive finite parsed size, so the following are **new conservative acceptance limits**, not claims about old outline enforcement: count 0..1500, positive safe-integer dimensions <=2147483647 EMU, paths <=1024 characters under ppt/ ending .xml without traversal/control characters/URL syntax, optional font <=256 characters without controls. Arrays must match count. Count zero is retained because open/outline does not require a nonempty deck. Missing defaultFont is accepted; explicit undefined is not a wire value and should be omitted by serialization. Nonstandard or oversized valid documents may be refused by these new limits; compatibility with every PPTX is not claimed.

`createPendingOutlineReply` freezes expected context/deadline, validates before consuming, rejects repeats and expiry, and permanently expires a timed-out local gate. It is a synchronous in-memory protocol helper, not durable replay protection; the future trusted session owns request creation, expiry and restart reconciliation. All operations remain production-disabled and no runtime call is installed.

## XLSX close protocol, with open explicitly deferred

Actual Rust source: `apps/sheets/native/xlsx-engine/src/protocol.rs:31-47` defines open(path, locale default zh, optional shortDateFormat) and close(sessionId); `:139-156` defines version/requestId/ok/result-or-error frame; `:563-572` closes and produces `{closed:true}`. `lib.rs:502` mints the engine session with `Uuid::new_v4().to_string()`. `lib.rs:602-609` rejects an unknown session. The native response does not carry sessionId; the trusted pending request, not the response, supplies that binding.

Unified close accepts `{profileId:'xlsx-edit-v1',command:'close',args:{}}` only. A future adapter must obtain engineSessionId from its current ExecutionHandle mapping, never from caller args. The Rust requestId is any String; canonical UUID request IDs are a new unified protocol choice, not an old engine guarantee. `validateXlsxCloseFrame` verifies the exact successful native frame and requestId, rejecting error/unknown-session responses and extra fields. `createPendingXlsxClose` snapshots trusted handle/session/request/generation, requires the current mapping still matches, validates the frame and consumes once. Expired, duplicate, different engine session or different job epoch/invocation fails. A close receipt is **not** StopObservation and must not release the OS reservation.

Open remains denied. Its actual `WorkbookMetadata` in `types.rs:9-43` and nested `SheetMetadata` cannot be certified by selecting only sessionId/sheets or accepting unknown extra fields. No invented summary API or generic JSON success path has been added. Future work should extract or generate strict schema-only definitions from the mature native types, covering every nested style/media/print/protection field, then independently review bounds and test real native fixtures before accepting open results. Host paths are never permitted in the unified caller request.
