# Actual minified PPTX candidate: generated-fixture IPC test

This stage executes the exact minified module built by the fixed candidate recipe
on a trusted PPTX freshly generated by PptxGenJS in the test. It does not accept an
uploaded document, enable a broker, certify isolation, mount a route or reach T06.

## Existing protocol, not a parallel stdin implementation

The existing runPptxSessionChild dispatcher uses Node advanced IPC, not standard
input/output. The new dedicated test entry verifies the independent expected
candidate digest, loads session.cjs and calls that existing exported dispatcher.

The test parent serializes these existing messages:

- open: id, m, binding(fileId/revision), Uint8Array bytes; reply count and EMU size.
- outline: id, m, expected generation, binding; reply is validated with the
  existing source-backed validatePptxOutline schema.
- apply: expected generation, binding, and fixture operations. The test verifies
  the reported transaction outcome and generation changes.
- export: expected generation and binding; the reply must carry that generation
  and a nonempty byte array of at most 1 MiB.
- close: id, m, binding; success requires an actual correlated reply with true.

Exit code zero is not substituted for close acknowledgement. The parent test
only exposes the operations above. This is not a newly secured child endpoint.
No second stdio wire schema or fake ExecutionHandle/ArtifactResult is introduced.

## Test-only process and bounds

Entry requires NODE_ENV=test, an explicit generated-fixture environment gate,
two fixed-purpose arguments and an existing IPC channel. Otherwise it exits 78.
The parent also requires NODE_ENV=test and unsafeGeneratedFixtureOnly=true.
Those gates are test intent checks, not provenance authentication of arbitrary
caller bytes.

The launcher uses the current trusted Node executable, a fixed entry/cwd, no
inherited execArgv, and a minimal two-variable environment. It never executes
the staged node.elf subset. It verifies candidate identity before forking;
the entry checks again before loading the module. Candidate directory/digest
are trusted test configuration, not user request paths or executable arguments.

One copied input is limited to 1 MiB, one request may be pending, at most eight
requests are permitted, and the process has a 10-second overall deadline.
stdout and stderr are each limited to 64 KiB of observed data. Correlated IPC
replies must have an exact envelope, satisfy method-specific bounds and match the outstanding id; existing
generation/binding errors terminate the fixture session. Error paths and explicit
disposal kill the test child and wait at most one second for its exit.
Cleanup failure is reported, never treated as a successful session.

IPC limits are checked after Node's advanced deserialization; they are not a
hard parser-allocation defense against a hostile peer. This channel contains a
known candidate and trusted generated data only. Ordinary directory
verify-then-load TOCTOU remains; this harness is not production admission.
A child exit or SIGKILL cleanup is not certified unit/cgroup stop evidence and
cannot release a production reservation or permit a save.

## Evidence and remaining gaps

The test opens the actual minified candidate and verifies that a batch cannot
create a slide and reference its new index in the same call. It then adds a
slide, reads the updated outline and writes a Chinese speaker note in a later
transaction. Exported bytes contain both the original slide text and the new
note; a new process reopens the export and sees both slides. Separate fresh child sessions reject wrong
generation and wrong binding and cannot be reused afterward. Wrong external
digest, replaced/missing candidate files and absent test gates are rejected.
Missing/replaced cases fail the pre-fork verifier; no alternative engine is used.
This is genuine functional coverage for this exact build recipe and fixture,
not comprehensive PPTX editing/rendering compatibility.

Run:

    DYOFFICE_ARTIFACT_SOURCE_ROOT=/path/to/exact/source node --experimental-strip-types --test apps/web/test/runtime-artifacts/pptx-candidate-ipc.test.mjs

In a complete checkout the source-root variable is unnecessary. The partial
workspace uses the previously checked materialization and existing dependencies.
No malicious archive fixtures or changes to ZIP security code are included.

Ubuntu/openEuler loader/library provenance, official Node signed checksums,
complete SBOM/license review, chosen font licensing and real host isolation
acceptance remain missing. The actual test uses the current cloud Node host,
not either target-distribution rootfs. Production remains disabled.
