# DyOffice Web host IPC classification (T00)

> Generated by `node tools/dyoffice/host-ipc-classification.mjs --write` from
> [host-ipc-classification.json](host-ipc-classification.json) and the AST inventory in
> `tools/audit-web-host.mjs`. Do not edit by hand; CI runs `--check`.

**Status: proposed.** Design mapping for T00. A rule is evidence about where a call must run in Web, not proof that it works there. Each member is verified only when the task named in verifyIn ships a passing adapter for it.

## Classes

| Class | Meaning |
| --- | --- |
| `browser-native` | Implemented in the browser with standard Web APIs or by moving existing TypeScript into a browser worker; no server round trip is needed for the call itself. |
| `server-api` | Needs the authenticated server: user files/revisions, personal preferences, public settings, provider gateway, chat history, retrieval or realtime command bridge. Identity comes from the server session, never from call arguments. |
| `isolated-worker` | Heavy or native processing (Rust sidecar, PDFium/pdf-lib on Node, headless Chromium export) run as an authorized job in the T08 sandbox; results return through T06 revisions or download. |
| `unsupported` | User-visible desktop feature not offered in Web scope. The BrowserHost capability catalog must report it as unsupported and the call must fail closed, never pretend success. |
| `desktop-only` | Electron window/shell/OS-path plumbing that the Web shell replaces structurally (routing, tabs, beforeunload, file ids instead of paths). No BrowserHost method is provided. |

Lifecycle is derived from the IPC operations the preload member performs:
`request` (invoke/sendSync), `subscription` (main→renderer events, returns an
unsubscribe), `notify` (fire-and-forget send) or `local` (no IPC). "Calls" counts
renderer call sites resolved by symbol, including shared workspace packages.
