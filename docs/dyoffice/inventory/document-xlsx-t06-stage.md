# Trusted XLSX library editing and T06 integration

This slice tests existing XLSX editing code with generated trusted fixtures and
real PostgreSQL/RustFS. It does not add a production adapter, enable job types,
replace the native worker, or bypass a failed host sandbox with ordinary fork.
Only x86_64 is in scope. Runtime isolation and desktop/Excel fidelity remain untested.

## Actual code path

`blankXlsxBuffer` creates a small valid workbook. Existing
`packages/xlsx-gateway/src/gateway/xlsx-gateway.ts::applyCellEditsToXlsx` performs
text, numeric, formula and bold-style edits and assembles real XLSX bytes using its
existing JSZip implementation. `assertOnlyTouchedEntriesChanged` checks unrelated
parts. The test then calls existing authenticated File/Lease/Revision services:

1. Import fixture through stage/receive/finish; acquire a real session edit lease.
2. Read verified source bytes and perform actual library editing in the test process.
3. Revision stage/receive creates an upload bound to the session, base and lease.
4. Explicit commit verifies storage and writes head/revision/receipt/outbox/quota.
5. Read committed bytes back from RustFS; reopen with JSZip and assert edited XML,
   style persistence, unchanged custom part and byte equality to the library output.

This is archive/content reopening, not native engine recalculation or Excel render
acceptance. Formula text is tested, not a computed cached value. There is no fake
exporter or mocked `native.savePlan`. The library is exercised only by a test over
trusted generated bytes, not installed as a server parsing fallback. Its original
ZIP dependency is reused unchanged; this slice does not change ZIP safety rules.

`createXlsxJobExecutor` and `createXlsxNativeWorker` remain the actual native job
route. Its existing host path requires a trusted binary manifest and working
systemd/root service setup. Those prerequisites are absent here, so that route
remains unverified rather than replaced.

## Cases

New `apps/web/test/local-integration/xlsx-save-t06.test.mjs` covers:
- Real text/number/formula/style edits, T06 save, exact receipt replay and reopen.
- Edit lease takeover rejects staging previously produced output.
- A real SQL trigger failure rolls back head, versions, receipts, outbox and quota;
  the exact staged upload succeeds after removing the test fault.
- Identical output bytes in another upload cannot replace the original commit input.
- A client exception injected after actual SQL commit recovers the original receipt
  with the same commitInput; it does not rerun editing or stage another upload.

All assertions query metadata through authenticated principal transactions.
Fault injection uses only the disposable test database. Each test uses the existing
restricted-role fixture with buildApp:false and a unique loopback RustFS bucket.
No shared fixture or production file is changed in this slice.

## Reproduction and source provenance

Source baseline: ClassesOver/DyOffice `40e0bff4`. The 65 xlsx-gateway source files
were checked against its recursive Git tree by exact Git blob hash before local
materialization. The three existing zip-gate package/source files also matched.
Local materialized sources and dependency links are not publication content.

With the existing disposable PG and S3 test environment variables:

```sh
node --import tsx --test --test-concurrency=1 apps/web/test/local-integration/xlsx-save-t06.test.mjs
```

`tsx` is required by an existing extensionless TypeScript dependency import. Do not
change the source to make strip-only execution work. No new dependency is proposed.
Test result counts must be taken from the final run; this document is scope, not
an isolation certificate. Full workbook feature coverage, native job delivery,
production authorization mapping and broker stop proof are outside this slice.

## Verified local result

The five cases above passed against real disposable PostgreSQL 17 and RustFS
1.0.6 on the current x86_64 test host (5/5, no skips; 7.46 seconds). Services were
stopped after the run and no test service processes remained. This is not a host
sandbox acceptance result.

An initial local run failed before any editing/T06 assertions because the partial
source materialization omitted `apps/web/package.json`; tsx consequently treated
the validation worker as CommonJS and rejected its top-level await. Restoring that
file byte-for-byte from the baseline (Git blob
`6da467e62ee007484ae01f2e8606e6aef067b2f8`) resolved the harness error. No validator,
authorization or test assertion was weakened. A full checkout already contains
this package metadata.
